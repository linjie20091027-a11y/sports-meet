# 教师端成绩录入修复与验证记录

## 修复目标

- 修复任课教师登录后成绩录入页出现空白或只显示空容器的问题。
- 对齐既有成熟成绩录入页的三步式流程：选择项目、筛选班级、录入并提交。
- 保持教师权限隔离，任课教师只能访问已分配项目的成绩录入能力。

## 根因结论

1. 默认任课教师账号仍绑定旧项目 ID，导致新初始化数据下看不到任何有效项目分配。
2. 成绩录入页默认选中的项目可能没有赛程或没有已审核参赛学生，前端缺少清晰空状态引导，表现为“页面没显示”。

## 本轮修复内容

- 规范默认任课教师的 `assigned_event_ids`，自动回补为当前有效项目。
- 扩展教师成绩录入接口，返回项目元数据、录入摘要、班级/轮次选项和 `readiness` 状态。
- 重构教师端成绩录入页面：
  - 自动优先选择更可操作的项目；
  - 增加步骤提示、摘要卡片、班级/轮次/关键词筛选；
  - 增加暂存、提交确认、清空筛选；
  - 为无赛程/无学生场景提供阻塞原因和快捷跳转。
- 补充自动化回归，覆盖有效项目分配、录入摘要、未分配项目拒访。

## 验证结果

- 页面资源验证：`/teacher.html` 返回 `200`，资源版本已刷新。
- 接口验证：
  - `/api/teacher/event/assignments` 正常返回有效项目分配；
  - `/api/teacher/event/results-entry` 正常返回 `summary` 与 `readiness`；
  - 未分配项目访问被正确拒绝。
- 自动化回归：`npm run test:all` 结果为 `84/85 PASS`。

## 已知遗留

- 当前仓库已有一个历史失败项：`GET /api/public/events/1` 返回 404。
- 该失败项在本轮修改前已存在，与教师端成绩录入修复无直接关系。
